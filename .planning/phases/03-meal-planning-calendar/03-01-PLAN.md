  <behavior>
- GET /api/meal-plans returns array of all meal plans with id, name, startDate, endDate
- POST /api/meal-plans accepts {name, startDate, endDate, notes?} and returns created meal plan
- GET /api/meal-plans/[id] returns meal plan with id, name, dates, notes, createdAt, updatedAt
- PUT /api/meal-plans/[id] updates name or notes, returns updated meal plan
- DELETE /api/meal-plans/[id] deletes meal plan (cascade deletes planned meals), returns 204
- GET /api/meal-plans/[id]/meals?start=YYYY-MM-DD&end=YYYY-MM-DD returns PlannedMeal[] with recipe details for date range
  </behavior>
  <action>
Create three route files following Next.js 16 pattern (await params, Zod validation, Prisma queries, date serialization):

**src/app/api/meal-plans/route.ts:**
- GET: `prisma.mealPlan.findMany()`, order by startDate desc, serialize dates to ISO strings
- POST: Validate {name: string, startDate: string, endDate: string, notes?: string}, create meal plan, return 201

**src/app/api/meal-plans/[id]/route.ts:**
- GET: `await params`, findUnique with id, return 404 if not found, serialize dates
- PUT: Validate {name?: string, notes?: string}, update meal plan, return updated plan
- DELETE: `prisma.mealPlan.delete({where: {id}})`, return 204 (cascades to plannedMeals via schema)

**src/app/api/meal-plans/[id]/meals/route.ts:**
- GET: `await params`, extract start/end from query string, validate YYYY-MM-DD format
- Query: `prisma.plannedMeal.findMany({where: {mealPlanId: id, mealDate: {gte: start, lte: end}}, include: {recipe: {select: {id, name, prepTime, cookTime, difficulty}}}, orderBy: {mealDate: 'asc'}})`
- Serialize dates and return PlannedMeal[] with nested recipe details
- Handle null recipeId (notes-only slots) gracefully

Error handling: ZodError → 400, Prisma NotFoundError → 404, generic → 500
